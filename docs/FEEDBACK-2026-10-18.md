# Feedback after the first hands-on session — 2026-10-18

Allan used the two-pane reader (branch `casus-ui`, built 2026-10-02) for the first time
on 2026-10-18 and gave the feedback below. It sits **above** both plans in priority:
nothing new starts until these are done. Items are grouped; the order inside a group is
his order of saying them. Decisions recorded the same day are marked **decided**.

## A. Run it easily, online, on a phone

1. **Hosted on his GitHub site**, working, so he can send the link to his old Latin
   professors. Target: `https://allan-valin.github.io/casus/` (project Pages site of the
   `casus` repo, built by GitHub Actions; Vite `base: '/casus/'`).
   - This **settles the Task 7 size gate: ship format 2 as is, commit `data/`.** Pages has a
     100 MB per-file limit (largest file here is `lemmas.json`, 4.9 MB) and a 1 GB site
     limit (whole `data/` 57 MB); Pages gzips JSON on the wire (7.3 MB for everything, a
     passage fetches ~100 KB). No trimming, no engine port.
   - Needs a `casus` remote (none exists yet), `main` merged, a Pages workflow.
2. **Runs well on a phone.** The spec said desktop two-pane; that is revoked. Narrow
   screens stack the sections vertically; tap targets large; `svelte-dnd-action` has touch
   support (`delayTouchStart` to keep scrolls from becoming drags).
   **Addendum (Allan, same day): the page adjusts to the resolution** — big and small
   monitors and every phone size must all read well. Fluid layout (`clamp()` type scale,
   container widths in `min()`/percent, breakpoints for stacking), not a fixed desktop
   width with one phone exception.
3. A **double-click launcher** for offline use stays wanted (copied from Desembarque), but
   the hosted site comes first.

## B. Colour, legibility, legend

4. **No mixed colours on unknown/unresolved blocks.** The striped fill is out. An unknown
   word (not in the lexicon) gets a **white background**. An ambiguous word gets a neutral
   background too; its surviving candidates are shown some other way (small case dots or
   badges on the pill), not by blending fills.
5. **Colour-blind-safe palette.** Hues must be told apart by anyone (deuteranopia,
   protanopia, tritanopia, grayscale). Use a published safe set (Okabe–Ito or Paul Tol) and
   **verify with a simulator**, not by eye. Where two cases collide for some viewer, add a
   **border difference** (solid / dashed / dotted / double, or border hue) as a second
   channel; the two-letter case badge stays as the third.
6. **A legend table** on the page: every colour and border → what it means (each case,
   number brightness, verb, function word, unknown, ambiguous, pinned, glued chunk).

## C. Arrangement controls

7. Beside *restore original order* and *auto-sort by case*: **word-order buttons SVO, SOV,
   VSO, VOS, OVS, OSV**. Subject = nominative block(s), Object = accusative, Verb = finite
   verb; everything else keeps its relative place after those. Ambiguous blocks go by
   their pinned reading, else first candidate (as auto-sort does).

## D. Layout and UX — "everything is jumbled, too close, the UX is terrible"

8. **More labels, clear page sections, air between them.** Every section gets a heading.
9. Button **Read → "Identify grammar"**, placed on the **right** of the text box, not the left.
10. **Bundled passages**: labelled as **demonstration samples**, placed **above** the text box.
11. The **transcribed text**: each selectable sentence gets a **visible border** so it is
    obvious it can be clicked.
12. **Layer toggles sit right next to the coloured blocks**, not far away.
13. **Era → explicit dictionary period.** Not "era" but something a non-classicist reads at
    a glance: e.g. "Dictionary period: Classical (Cicero, Caesar, 1st c. BC)", with the
    other periods named with dates and an example author.
14. **Instructions on screen**: that a block opens the dictionary on click and can be
    dragged is not obvious to anyone but Allan. Short inline hints, **plus a "?" help
    button** that explains what is on screen and **lists every dictionary and resource used**
    (Whitaker's WORDS, pt.Wiktionary via Wiktextract, Perseus/Latin Library for the
    samples, svelte-dnd-action, licences).
15. **Clicking the same block again closes the dictionary.**
16. **Block pool uses the full screen width**, same as the text box and the transcription.
    Dragging a chunk like *in principio* in the narrow pane moves too much and is hard to
    place.
17. **Drag preview instead of instant reflow.** Blocks must not slide while aiming. Show an
    insertion caret `|` between the two blocks the pointer is aiming at; **move only on
    release.** `svelte-dnd-action` reflows live by design and has no caret-only mode
    (checked README 0.9.79) → needs a **spike**: either a drop-indicator option in another
    MIT library (Atlassian's pragmatic-drag-and-drop, Apache-2.0, has drop indicators) or a
    small hand-rolled pointer-event drag (ghost follows pointer, nearest gap computed, caret
    drawn, splice on release). Either way the glued-chunk and touch cases from
    `spikes/drag/measure.mjs` must still pass.
18. **Gloss language toggle showed no difference** → because `glosses.pt.json` is not built
    (core plan Task 8). Build it. Rename the control **"Dictionary language"** and show which
    one is active; the "?" lists all dictionaries.
19. **Design hints from Desembarque**: the stylised overlay used for its "dropdown" (the
    readings box) is the model for the dictionary and candidate panels; **different colours**
    for buttons and background than Desembarque's.
20. **Export JSON / Markdown** go to a **top corner** of the screen, each with a label saying
    what will happen (what the file contains, where it goes).

## E. Decided the same day (also in the morning's feedback)

- **UI language is a flag** (English ⇄ pt-BR) covering chrome and dictionary.
- **v2 OCR uses Desembarque's engine** (kraken PP-OCRv6 + second reading), not tesseract.js.
  Spec §10.2 and §13 to amend.
- **All Desembarque GUI features copy over**: `say()` action log + "what is happening"
  panel, busy bar + 4 s slow line, overlay box pattern, pinned toolbar + Ctrl+wheel zoom,
  double-click launcher. Rewritten in Svelte.
- Merge `casus-core` → `main` → `casus-ui`; add `LICENSE`; build PT glosses.

## F. Question asked: other languages

Any language with cases and declensions; the dictionary half for any language including
Arabic and Asian scripts; an alphabet-learning tool. **Latin first.** Assessment in the
session notes (memory `app-latin-case-blocks`); summary:

- Portable now: segment/tokenize boundary, candidate model, cascade shape, UI, persist,
  export, colour system (hue per case works for any case language).
- Latin-bound now: the build (Whitaker's fixed-column format), the analysis code letters
  (format 2 assumes Latin's case/number/gender/degree and verb categories), the agreement
  and government rules, the preposition table, enclitic list.
- Source for other languages: Wiktextract (CC BY-SA) carries inflection tables and glosses
  for Greek, German, Russian, Sanskrit, Finnish, Arabic, Japanese, Korean… one build per
  language, same shard writer once the code alphabet is per-language.
- Alphabet tool is a separate small app sharing the dictionary data, not the block pool.
